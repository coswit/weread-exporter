# weread-exporter 重构设计

日期:2026-09-07
状态:已确认(用户已批准方案 A 与各设计节)

## 背景与目标

现有工具(`export_precise.py` + `download_images.py`)通过 Playwright + Canvas Hook
逐页捕获微信读书网页版的图文内容,已能全本导出,但存在三个问题:

1. 章节文件以纯序号命名(`0001.md`),不可读
2. 只能从第一章一路导到全书末尾,无法选择章节
3. 每页固定 sleep 约 1–2 秒,整体偏慢

重构目标(用户确认的需求):

- **纯章节标题命名** md 文件(如 `第1章 阅读前的准备工作.md`)
- **可选章节导出**:命令行参数 `--chapters` 与交互式选择双通道
- **流畅快速**:自适应等待替代固定 sleep,目标 0.3–0.6 秒/页
- 保留三大现有能力:图文交错+图片并发下载、断点续传、合并全本 md

## 技术方案(已选定:方案 A)

**保留已验证的捕获内核,重写流程层。**

- 保留:Canvas fillText Hook、双页拆分(`split_spread`)、文字/图片按屏幕 y 坐标交错
  (`build_page_blocks`)、段落合并(`render_chapter_md`)、视口图片过滤。
- 重写:整体流程编排 —— 目录全量扫描、章节选择、定点跳转、按标题落盘、
  断点续传定位、速度策略、CLI。

否决的备选:

- 模块化 Python 包:对单人 ~800 行工具属过度工程,功能零增益。
- 内部 API 直取:章节内容加密需逆向、接口脆弱,且无法保证图文按阅读位置
  交错(与保留图文交错的需求冲突)。

## 总体架构

单文件 `export.py` 取代现有两个脚本。`download_images.py` 的能力被吸收:

- 导出完成后自动并发下载图片(现状保持)
- 新增 `--download-only` 模式:只补下缺失图片,不翻页

主流程:

```
登录(复用 cache/browser_profile)
→ 打开书
→ 扫描完整目录(打开目录面板,增量滚动到底,按 DOM 顺序收集条目 → _catalog.json)
→ 解析选择(--chapters 参数;无参数则列出编号+标题,交互输入;回车=全部)
→ 持久化选择到 _selection.json(供断点续传复用)
→ 逐段导出:
    目录面板滚动定位到选中区间起点条目 → 点击跳转
    → ArrowRight 逐页翻页捕获 → 章节切换即落盘上一章
    → 当前章节越过本段最后一个选中章节 → 落盘并跳转下一段起点
→ 全部选中章节完成
→ 并发下载图片(images/)
→ 按目录顺序合并选中章节为 output/书名.md
```

## 目录扫描与章节选择

### 目录全量扫描

- 打开目录面板(`button.readerControls_item.catalog`),对列表滚动区域
  (`.readerCatalog_list_scroll_area`)做增量滚动:每滚一批收集当前渲染的
  `.readerCatalog_list_item`,直到滚到底且无新增条目。
- 按首次出现顺序(而非收集批次)确定条目序号;以条目元素内标题文本的稳定
  标识(元素引用或文本)去重。
- 每个条目的标题从条目内的标题子元素提取(如 `.readerCatalog_list_title`);
  取不到时回退整个条目的 textContent,并剥离混入的进度文字
  ("当前读到 N%""书签"等拼接段)。
- 存 `_catalog.json`:`[{idx, title}]`,1-based idx 与展示编号一致。
- **注意**:即便做了剥离,个别目录标题仍可能与阅读器顶部标题栏
  (`.renderTargetPageInfo_header_chapterTitle`)的文本不完全一致,
  因此文件命名一律用顶部标题栏文本;目录标题只用于编号、定位与点击。

### 选择语法

- `--chapters "5-12,18"`:逗号分隔,支持单号与闭区间,空格容忍,忽略越界
  编号(警告),1-based 对应目录展示编号。
- 交互模式:无 `--chapters` 参数时,打印编号+标题清单(超过一定数量分屏或
  直接全量打印,简单起见全量打印),提示输入同语法;回车或 `all` = 全部。
- 解析为选中 idx 集合,升序排序后切分为连续区间段,供跳转导出。

### 当前章节定位

- 翻页后顶部标题变化 → 从上次匹配的目录位置向前搜索下一个匹配标题。
  匹配策略:先去除空白后全等;失败则互相包含匹配(顶部标题是目录标题的
  前缀,或反之)——兜住目录标题剥离不净的情况。容忍重复标题(如多个
  "注释")。
- 单调前进假设:顺序翻页时目录位置不回退;向前搜索找不到则视为未知名,
  记警告并继续(不中断导出)。

### 不连续选择的跳转

- 一段(连续区间)导完:保存该章后,重新打开目录面板,滚动到下一段起点
  条目并点击跳转,继续翻页导出。
- 目录跳转失败(找不到条目/点击超时):重试一次,仍失败则会话报错,
  交给会话循环重开(见错误处理)。

## 文件命名与输出布局

```
output/<book_id>/
├── _catalog.json        # [{idx, title}] 完整目录
├── _selection.json      # 选中章节 idx 列表(本次导出范围,供续传)
├── chapters/
│   ├── 扉页.md
│   ├── 第1章 阅读前的准备工作.md      ← 纯标题命名
│   └── ...
├── images/              # chXXXX_imgNN.jpg,不变
└── raw/                 # 每章 json,新增 catalog_idx 字段
```

- 文件名 = 净化后的顶部标题栏文本:替换 Windows 非法字符
  `<>:"/\|?*` 与控制字符为 `_`,去除首尾空白与结尾的 `.`/空格
  (Windows 限制),截断到 80 字符。
- 同名去重:同一本书内重复标题追加 ` (2)`、` (3)`(按目录序)。
- raw json 结构:`{"title", "catalog_idx", "file", "images": [...], "text_len"}`。
- 断点续传依据 raw 中的 `catalog_idx` 判断进度与剩余区间,不再依赖文件名排序。
- 合并文件 `output/书名.md`:只含选中章节,按 catalog_idx 升序,章节间以
  `---` 分隔(现状保持)。

## 速度策略

- 翻页后自适应等待:每 ~120ms 轮询 `window.__wr_count()`,连续两次读数一致
  且距翻页 ≥250ms 即认为渲染稳定;硬超时 8 秒兜底。
- 预期 0.3–0.6 秒/页(现约 1–2 秒)。
- 安全网(保留现状):stale 计数 —— 连续 10 页无新内容判定卡住;渲染进程
  崩溃捕获;异常时会话循环重开浏览器续传。
- 目录跳转后的固定 sleep 收紧为同类稳定等待。

## 断点续传

- 会话循环结构保留:会话异常保存已捕获内容后退出,外层最多连续重试 3 次
  (连续 3 次失败则停止,保留现场)。
- 重开会话时:重读 `_catalog.json` 与 `_selection.json`;若命令行未显式传
  `--chapters` 且存在 `_selection.json`,沿用之;从 raw 中最后一个已完成的
  `catalog_idx` 推导剩余区间,目录点击跳到断点章节(处理"章中途崩溃"的
  覆盖重写,与现状一致)。
- 显式传 `--chapters` 始终覆盖 `_selection.json`。

## 错误处理

- 保留:残留浏览器进程清理(`kill_stale_browsers`)、`.tmp` + `os.replace`
  原子写、显式 utf-8 编码、扫码登录等待(10 分钟超时)。
- 新增:章节选择解析的越界/非法输入警告与重提示;目录条目定位失败重试;
  未知章节标题(目录中找不到)记警告不中断。
- 顶部标题为空(如某些插图页跨页)沿用现状:视为同章节内容继续累积。
